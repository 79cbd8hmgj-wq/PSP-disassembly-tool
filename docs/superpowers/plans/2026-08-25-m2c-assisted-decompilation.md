# Phase 4 m2c Assisted Decompilation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add traceable single-function m2c-assisted C generation to Phase 3 PSP decompilation projects.

**Architecture:** Read the existing project function model, isolate m2c behind a subprocess adapter, and materialize assembly/C/metadata artifacts without importing GPL code. Preserve m2c's PSP-unsupported instruction markers as warnings rather than rewriting instruction semantics.

**Tech Stack:** Python 3.10+, stdlib `subprocess`/`tempfile`/`json`, pytest, supplied m2c source, existing pspdisasm models/CLI.

**Spec:** `docs/superpowers/specs/2026-08-25-m2c-assisted-decompilation-design.md`

## Global Constraints

- Keep the `pspdisasm` core MIT; do not import, vendor, or copy GPLv3 m2c code.
- Default m2c target is exactly `mipsel-gcc-c`.
- Never invent semantics for unsupported Allegrex/VFPU instructions.
- Preserve existing Phase 1-3 public behavior and tests.
- A non-zero m2c exit must not overwrite an existing successful C artifact.
- Generated metadata must use project-relative artifact paths when possible.
