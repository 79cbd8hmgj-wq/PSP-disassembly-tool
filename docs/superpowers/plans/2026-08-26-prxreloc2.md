# Phase 7E PT_PRXRELOC2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Decode PSP `PT_PRXRELOC2` compressed relocation streams into normalized relocation metadata and provide explicit, pure relocation-word application primitives without inventing a runtime load address.

**Architecture:** Add a focused `prxreloc2.py` decoder/application module and extend `Relocation` only with defaulted provenance fields. `prx.py` remains the orchestration boundary: it catches malformed Type-B streams as per-segment warnings and combines valid decoded records with existing Type-A records. Disassembly continues to consume original bytes until a later explicit load-view phase can apply both relocation families consistently.

**Tech Stack:** Python 3.11+, dataclasses, existing ELF32/PRX models, pytest, synthetic PSP ELF fixtures.

**Spec:** `docs/superpowers/specs/2026-08-26-prxreloc2-design.md`

## Global Constraints

- Do not copy GPL PPSSPP implementation code into the MIT core.
- `PT_PRXRELOC2` decoding must be little-endian and bounded by the relocation program header's declared file extent.
- Do not infer or choose a runtime PSP load address.
- Do not automatically mutate bytes before spimdisasm/Splat analysis in Phase 7E.
- Malformed Type-B streams are isolated as PRX-analysis warnings.
- Existing Type-A relocation output remains compatible.
- Ambiguous HI16 reuse mode `0x08` must be preserved as unresolved rather than guessed.
